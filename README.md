# 🛡️ Ramad Assistant (עוזר אישי ומנטור לרמ"ד)

**Ramad Assistant** הינה מערכת **Multi-Agent** מתקדמת מבוססת בינה מלאכותית (LLM-Native), שפותחה במיוחד עבור **ראש מדור (רמ"ד) טכנולוגי-מודיעיני**.

המערכת פועלת כעוזר אישי, מנהל משימות מבצעי, מנהל הון אנושי ופיתוח אנשים, ו**"מראה פיקודית"** סוקרטית. המערכת מחוברת לממשק **Telegram** (תומכת בקלט קולי וטקסטואלי) ומופעלת על גבי **Google Cloud Run** עם מודל **Google Gemini 3.8 Flash** וארכיטקטורת **LangGraph**.

## 🎯 חזון ועקרונות פיקודיים (תפיסת תפקיד)

המערכת נבנתה סביב תורת הפיקוד האישית של הרמ"ד ומשמשת כ"מראה פיקודית" לשמירה על חמשת עקרונות הברזל:

1. **שגרות יומן ועומסים – *"מה שלא ביומן לא קורה!"***  
   - שריון חלון זמן קבוע לתכנון לו"ז שבועיים קדימה.  
   - קביעת פגישות ודיונים של 30 דקות כברירת מחדל.  
   - קו אדום: יציאה הביתה בימי שלישי ב-16:00 למשפחה ולילדות.
2. **אחריות מקיפה – *"האויב של האחריות הוא אחריות מקיפה"***  
   - מוודאים שהמערכות הקיימות עובדות הרמטית לפני שמוסיפים פיצ'רים חדשים.  
   - לדעת להגדיר *מה לא עושים* ולעמוד בלחצי דרישות.
3. **אנשים וחניכה – *"הרמ"ד הוא המערכת"***  
   - הפקודים רוצים שיראו אותם, שיילחמו עליהם ושייתנו להם גב פיקודי מלא.  
   - קיום שיחות 1-על-1 חודשיות, חוזי חניכה עם יעדים אישיים ומקצועיים, ומשוב ישיר ודוגרי.
4. **איכות וחוב טכנולוגי – *"אין חוב טכנולוגי שקוף!"***  
   - כל מעקף או טלאי זמני בקוד נרשם מיד עם תאריך יעד ברור לפתרון שורש ארכיטקטוני.
5. **דוגמא אישית ומנהיגות**:  
   - קור רוח, אופטימיות, ומועילות מבצעית הקודמת ליעילות טכנולוגית.

## 🏗️ ארכיטקטורת המערכת והסוכנים

המערכת בנויה בארכיטקטורת **Multi-Agent** עם נתב-על (Supervisor) וסוכנים מתמחים:

```mermaid
flowchart TD
    User["משתמש (Telegram - קול / טקסט)"] --> Gateway["FastAPI Gateway / Webhook"]
    Gateway --> AudioProc["Voice Processor (Gemini Multimodal Transcription)"]
    Gateway --> Supervisor["Supervisor Router (Gemini 3.8 Flash Intent Classifier)"]
    
    Supervisor -->|משימות, תג"בים, דחיות| TaskAgent["Task & Tagab Agent"]
    Supervisor -->|אנשים, צוותים, נע"ת, 1-על-1, שחרורים| HRAgent["HR & People Agent"]
    Supervisor -->|דילמות, שיקוף סוקרטי, ארכיטקטורה ושיחה כללית| MentorAgent["Command Mentor & System Expert"]

    subgraph Data & Vector Layer
        TaskAgent <--> TaskDB["Personal Tasks DB (SQLite / Postgres)"]
        HRAgent <--> PeopleDB["Soldiers & Teams DB\n(ניהול - אנשים ופיתוח)"]
        MentorAgent <--> DoctrineDB["Doctrine Vector Store (Embeddings & Principles)"]
    end

    TaskAgent --> Responder["תשובה שיחתית טבעית בעברית (Gemini Tool Calling)"]
    HRAgent --> Responder
    MentorAgent --> Responder
    Responder --> Gateway --> TelegramOut["Telegram Bot Client"]
```

- **סוכן משימות ותג"בים ([`TaskAgent`](file:///home/netancoh/Desktop/MyProjects/ramad-assistant/src/ramad_assistant/orchestrator/task_agent.py))**:

- **סוכן מנטור פיקודי ומומחה המערכת ([`CommandMentorAgent`](file:///home/netancoh/Desktop/MyProjects/ramad-assistant/src/ramad_assistant/orchestrator/mentor_agent.py))**:

## 🗄️ מודל הנתונים (Database Schema)

מסד הנתונים מנוהל באמצעות [`TaskRepository`](file:///home/netancoh/Desktop/MyProjects/ramad-assistant/src/ramad_assistant/db/repository.py):

| טבלה | תיאור ושדות מרכזיים |
|---|---|
| `soldiers` | נתוני חיילי המדור: שם מלא, שיוך לצוות, סוג שירות (חובה/קבע/מילואים), דרגה, סטטוס ת"ש, סטטוס אקדמי/מצטיין, תאריך שחרור, נע"ת נוכחי, השכלה, והערות מפקד. |
| `teams` | צוותי המדור (טטריס, קסבה, טקסס, ארמורי, ברוקלין, רוחבי), ראשי צוותים ותיאור. |
| `naat_history` | היסטוריית נושאי אחריות תחומיים לחיילים (תפקיד, תאריך התחלה וסיום). |
| `mentorship_contracts` | חוזי חניכה שנתיים: יעדים אישיים, יעדים מקצועיים, מועד שיחת 1-על-1 אחרונה ותאריך יעד לשיחה הבאה (ללא חריגה מ-30 יום). |
| `personal_tasks` | משימות אישיות של הרמ"ד: כותרת, תג"ב (`tagab_at`), עדיפות (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`), סטטוס (`OPEN`, `DONE`, `CANCELLED`, `POSTPONED`), מונה דחיות וסיבת הדחייה האחרונה. |
| `reflection_logs` | תיעוד תחקור עצמי דו-שבועי: תשובות ל-3 שאלות השיקוף, 2 נקודות לשימור, 2 נקודות לשיפור ותובנות. |
| `command_doctrine` | צ'אנקים ווקטורים של תורת הפיקוד עם תמיכה בחיפוש דמיון קוסינוס (Cosine Similarity). |

## 🧠 מנוע השיחה וה-Tool Calling

המערכת פועלת במודל **Conversational AI מלא**:
- **Native Tool Calling**: הסוכנים אינם פולטים תבניות טקסט קבועות ("רובוטיות"). הם מפעילים פונקציות מוגדרות מול מסד הנתונים, מקבלים את התוצאות, ומנסחים תשובה זורמת וחכמה בעברית טבעית (כמו בשיחה מול ChatGPT או Gemini).
- **זיכרון שיחתי מתמשך (Multi-Turn Chat History)**: שמירת 15 חילופי הדברים האחרונים פר משתמש, המאפשרת שאלות המשך טבעיות בהקשר מלא (*"מי המפקד שלו?"*, *"תמחק אותה"*, *"מה עוד נשאר?"*).
- **Voice In / Text Out**: הודעות קוליות בטלגרם מתומללות ישירות באמצעות היכולות המולטי-מודאליות של Gemini, ומנותבות מיידית לסוכן המתאים.

## 💬 יכולות מרכזיות ודוגמאות שימוש

### 1. משימות ותג"בים
- **פתיחה**: *"תפתח משימה לתג\"ב מחר ב-12:00: להכין מצגת סטטוס לרע\"ן"*
- **בירור משימות**: *"מה המשימות שלי?"* / *"מה המשימות הפתוחות?"*
- **דחייה (עם סיבה)**: *"תדחה משימה #1 למחר בערב בגלל דיון מבצעי דחוף"*
- **סיום יחידני או גורף**: *"סיימתי משימה #2"* / *"סיימתי את כל המשימות"*
- **מחיקה קשיחה**: *"תמחק את המשימה של המצגת לרע\"ן"* / *"תמחק את כל המשימות"*
- **דוח בוקר**: *"דוח בוקר יומי"*

### 2. אנשים, צוותים וחניכה
- **בירור פרופיל חייל**: *"מי זה אביהוא דוד אהרון?"* / *"ספר לי על טל שיף"*
- **מבנה המדור והצוותים**: *"מה הצוותים שלי?"* / *"כמה צוותים יש לי?"*
- **חיילים לפי צוות**: *"מי בצוות ברוקלין?"* / *"רשימת חיילים בצוות טטריס"*
- **שחרורים קרובים**: *"מי משתחרר ב-3 החודשים הקרובים?"*
- **תיעוד שיחת 1-על-1**: *"קיימתי שיחת 1-על-1 עם דניאל כהן: דיברנו על אתגרים טכנולוגיים ומוטיבציה לקבע"*
- **שיבוץ נע"ת**: *"שבץ נע\"ת לאורי לוי: אחראי הדרכה מדורי"*
- **חוזה חניכה**: *"עדכן חוזה חניכה לדניאל כהן: יעד אישי: ביטחון עצמי בדיונים, יעד מקצועי: הובלת מודול ענן"*

### 3. מנטור פיקודי ושיחה כללית
- **דילמות ניהוליות ועומס**: *"אני טובע בדיונים ולא מספיק להגיע למשימות הליבה"*
- **התייעצות על תפיסת תפקיד**: *"הרע\"ן לוחץ על הוספת עוד פיצ'ר למערכת לקראת התרגיל, איך לגשת לזה?"*
- **שאלות על המערכת והארכיטקטורה**: *"איך המערכת הזו בנויה ואיזה סוכנים קיימים בה?"*
- **תחקור עצמי דו-שבועי**: תהליך יזום (באמצעות קרון או פקודה) למענה על 3 שאלות שיקוף וגזירת נקודות לשימור ולשיפור.

## 💻 התקנה והרצה מקומית

### דרישות מקדימות:
- Python 3.12 ומעלה.
- מפתח API פעיל מ-Google AI Studio (`GEMINI_API_KEY`).
- טוקן לבוט טלגרם מ-BotFather (`TELEGRAM_BOT_TOKEN`).

### שלבי התקנה:
```bash
# 1. שכפול המאגר
git clone https://github.com/netanelC/ramad-assistant.git
cd ramad-assistant

# 2. יצירת סביבה וירטואלית והתקנת תלויות
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

# 3. הגדרת משתני סביבה בקובץ .env
cat <<EOF > .env
TELEGRAM_BOT_TOKEN="your_telegram_bot_token"
GEMINI_API_KEY="your_gemini_api_key"
ALLOWED_TELEGRAM_USER_IDS="123456789"
API_SECRET_KEY="your_internal_secret_key"
DATABASE_URL="sqlite:///./ramad_tasks.db"
EOF

# 4. זריעת נתוני דוקטרינה וחיילים
python -m ramad_assistant.db.seed_doctrine
python -m ramad_assistant.db.seed_soldiers "ניהול - אנשים ופיתוח.csv"

# 5. הרצת השרת המקומי
uvicorn ramad_assistant.gateway.app:app --reload --port 8080
```

## ☁️ פריסה לענן (Google Cloud Run)

המערכת רצה ומנוהלת ב-**Google Cloud Run**:

```bash
# 1. הכנת קובץ .env.yaml לפריסה (מאובטח ואינו במאגר הציבורי)
cat <<EOF > .env.yaml
TELEGRAM_BOT_TOKEN: "your_bot_token"
GEMINI_API_KEY: "your_gemini_api_key"
ALLOWED_TELEGRAM_USER_IDS: "123456789"
API_SECRET_KEY: "your_secret"
EOF

# 2. פריסה ל-Cloud Run
gcloud run deploy ramad-assistant \
  --source . \
  --region me-west1 \
  --allow-unauthenticated \
  --env-vars-file .env.yaml

# 3. הגדרת Webhook מול Telegram
curl -F "url=https://<YOUR-CLOUD-RUN-URL>/webhook/telegram" \
  https://api.telegram.org/bot<YOUR-BOT-TOKEN>/setWebhook
```
